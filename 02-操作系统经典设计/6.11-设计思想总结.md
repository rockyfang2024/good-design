# 6.11 设计思想总结

> 操作系统几十年解决的核心问题，与现代 AI Agent 系统面临的问题高度相通。

## OS → AI Agent 设计对照

```
操作系统问题               →    AI Agent 对应设计
────────────────────────────────────────────────────────
进程调度（谁先用）          →    LLM 调用的 Budget 控制（iteration_budget）
虚拟内存（给每个进程独立空间）→ Session 隔离（不同 session_id 不混淆）
页置换算法（内存不足时换出）→ Context 压缩（历史太长时压缩中间段）
Mutex/Semaphore（并发安全）→  工具执行的并发控制（_should_parallelize_tool_batch）
RCU（读多写少优化）         →    Session 历史只读，append-only
日志文件系统（断电恢复）     →    Trajectory 保存（会话轨迹持久化）
中断/系统调用（安全边界）   →    危险工具的 approval 审批链
零拷贝（减少不必要的数据搬运）→ Prompt Caching（减少重复传输）
cgroup（资源隔离）           →    多租户 Agent 的资源配额
OOM Killer（内存压力下的决策）→ LLM 降级策略（模型降级、回复截断）
EEVDF（延迟敏感任务调度）   →    流式输出的优先级调度
```

## 核心设计原则

### 1. 分层抽象

```
应用 → 系统调用 → 内核子系统 → 硬件
  ↑
  应用不需要知道页表怎么工作
  应用不需要知道哪个进程先跑
```

### 2. 利用局部性

```
CPU 缓存 ← 利用时间局部性（最近用过的指令/数据可能再用）
页置换 ← 利用空间局部性（相邻地址的数据可能一起访问）
CDN ← 利用访问局部性（热门内容被高频访问）
```

### 3. 没有银弹

```
MLFQ：交互优先 vs CFS：公平优先
选择取决于场景，没有"最好"的调度器

MMU：硬件支持 vs 软件模拟
选择取决于成本，没有完美的解决方案
```

### 4. 权衡是设计

```
性能 ↑ = 复杂度 ↑ = 维护成本 ↑
实时调度：延迟确定 ↑ = 吞吐量 ↓
大页（HugePages）：TLB miss ↓ = 碎片化 ↑
```
