## 设计思想总结

```
操作系统问题               →    AI Agent 对应设计
────────────────────────────────────────────────────────
进程调度（谁先用）          →    LLM 调用的 Budget 控制
虚拟内存（给每个进程独立空间）→ Session 隔离（不同 session_id 不混淆）
页置换算法（内存不足时换出）→ Context 压缩（历史太长时压缩中间段）
Mutex/Semaphore（并发安全）→  工具执行的并发控制
RCU（读多写少优化）         →    Session 历史只读，append-only
日志文件系统（断电恢复）     →    Trajectory 保存（会话轨迹持久化）
中断/系统调用（安全边界）   →    危险工具的 approval 审批链
零拷贝（减少不必要的数据搬运）→ Prompt Caching（减少重复传输）
cgroup（资源隔离）           →    多租户 Agent 的资源配额
OOM Killer（内存压力下的决策）→ LLM 降级策略（模型降级、回复截断）
EEVDF（延迟敏感任务调度）   →    流式输出的优先级调度
```

## 核心设计原则

1. **分层抽象**：每一层只关注自己的接口，下层为上层服务
2. **利用局部性**：时间局部性 + 空间局部性是大多数优化的基础
3. **没有银弹**：每次设计选择都是权衡，不存在"最好"的方案
4. **权衡是设计**：性能、复杂度、可维护性三者永远在拉锯
