# 6.6 进程间通信：消息传递

> 两个独立进程怎么交换数据？
>
> **类比**：两户人家住在一栋楼里，不能直接进对方家门，但可以通过：门铃对讲机（一方说话一方听）、邮筒（写信放进去，对方来取）、共享阳台（两人站在同一个阳台上能看到对方的东西）。每种方式速度和便利性不同。

---

## 生活场景：邻居之间怎么传递东西？

```
场景：你住 301，你朋友住 302，你们是"独立的两家人"（两个进程）

方式 1：门铃对讲机（管道）
  你：对讲机说"把盐递给我"
  朋友：通过门缝把盐塞过来
  特点：单向，快的，但一次只能说一件事

方式 2：邮筒寄信（消息队列）
  你：写封信，放到邮筒
  朋友：开信箱取信
  特点：异步，有边界（每封信是完整的）

方式 3：共享阳台（共享内存）
  两人站到同一个阳台上
  你把东西放阳台桌上，朋友直接拿
  特点：最快（零拷贝！），但要自己保证不打架（同步）

方式 4：微信发消息（Unix Socket）
  你发消息，朋友收到
  特点：双向，有消息边界，可跨机器
```

---

## 问题

- 无名管道：亲缘进程才能通信
- 信号：只能传递信号码，不能传数据
- 共享内存：最快，但需要同步
- 消息队列：可以传结构化数据

---

## 经典解法

### 方式一：管道（Pipe）——"对讲机"

**类比**：门铃对讲机，只能单向传话，一方说另一方听。

```
进程 A（说话）                    进程 B（听话）
      │                               ▲
      │ write("开门")                  │
      ├─────────── pipe ───────────────┤
      │                               │
```

```c
// 创建管道
int pipefd[2];
pipe(pipefd);  // pipefd[0]=读端, pipefd[1]=写端

// 进程 A：写入
write(pipefd[1], "hello", 5);

// 进程 B：读取
read(pipefd[0], buf, 5);
```

**特点**：
- **字节流**：没有消息边界，对方读到的是连续的字节流
- **单向**：一旦创建，通常父进程用一端、子进程用另一端
- **同步**：读端没数据会阻塞，写端写满（管道默认 64KB）也会阻塞

**为什么叫"无名"管道**：普通 pipe 没有名字，只能用于有亲缘关系的进程（父子、兄弟）。有名字的管道叫 FIFO（命名管道），可以用于任意进程。

---

### 方式二：消息队列——"邮筒"

**类比**：把信投进邮筒，对方开信箱取。每封信有明确的收件人和内容。

```c
// 发送消息
msgget(key, IPC_CREAT);
msgsnd(qid, &msg, strlen(msg.text), 0);

// 接收消息
msgrcv(qid, &msg, sizeof(msg.text), msg_type, 0);
```

**为什么比管道好**：

| | 管道 | 消息队列 |
|---|---|---|
| 生命周期 | 随进程（无名）/ 随内核（有名字） | 随内核，直到被显式删除 |
| 方向 | 单向 | 双向 |
| 消息边界 | 无（字节流） | 有（每条消息独立） |
| 查找 | 只能从头部读 | 可以按 type 随机读 |

```
管道 = 水管，流进来什么顺序出去就什么顺序
消息队列 = 邮筒，每封信都是独立的包裹

管道像打电话（对方不接你就一直等）
消息队列像发 EMS（放进去，对方有空再取）
```

---

### 方式三：共享内存——"共享阳台"

**类比**：两人站到同一个阳台上，桌上的东西直接共享。

```c
// 进程 A：创建共享内存
int shmid = shmget(IPC_KEY, 4096, IPC_CREAT | 0666);
void *shm = shmat(shmid, NULL, 0);
strcpy(shm, "hello from A");

// 进程 B：连接到同一块共享内存
int shmid = shmget(IPC_KEY, 4096, 0666);
void *shm = shmat(shmid, NULL, 0);
printf("%s\n", shm);  // 直接访问，不需要系统调用！
```

**为什么最快**：
- 管道/消息队列：数据从用户态 → 内核缓冲区 → 用户态（至少 2 次拷贝）
- 共享内存：直接访问物理内存，不同进程映射到同一块（零拷贝）

**警告**：共享内存不提供同步，需要额外用 Mutex/Semaphore。

---

### 方式四：Unix Domain Socket ——"微信"

**类比**：比管道更强大——双向、有消息边界、可传文件描述符。

```c
// 服务端
int usfd = socket(AF_UNIX, SOCK_STREAM, 0);
bind(usfd, addr);
listen(usfd, 5);
accept(usfd, &client_addr);

// 客户端
int usfd = socket(AF_UNIX, SOCK_STREAM, 0);
connect(usfd, addr);
send(usfd, msg, len, 0);
```

**Unix Socket 的特殊能力**：可以传递"文件描述符"（FD passing）。进程 A 打开了文件，获得 fd=5，可以把这个 fd 通过 Unix Socket 传递给进程 B，进程 B 也能访问同一个文件。

## IPC 演进：System V vs POSIX

```
System V IPC（1983 年，Unix 的"老一代"）：
  msgget() / msgsnd() / msgrcv()   → 消息队列
  semget() / semop() / semctl()     → 信号量
  shmget() / shmat() / shmdt()      → 共享内存

  特点：功能强大，但接口复杂，像功能机

POSIX IPC（2001 年，现代化）：
  mq_open() / mq_send() / mq_receive()  → 消息队列
  sem_open() / sem_wait() / sem_post()   → 信号量
  shm_open() / mmap()                     → 共享内存

  特点：接口更简洁，符合 Unix 设计哲学（一切皆文件）
```

---

## IPC 性能对比

| 方式 | 延迟 | 吞吐量 | 适用场景 |
|------|------|--------|---------|
| 管道/Unix Socket | 低（内核缓冲） | 中 | 简单数据流、父子进程通信 |
| 消息队列 | 中（有内核拷贝） | 中 | 结构化消息、异步处理 |
| 共享内存 | 极低（零拷贝） | 极高 | 高频大数据交换（进程间） |
| RPC（gRPC/Thrift） | 高（有序列化） | 中 | 跨语言、跨机器 |

```
共享内存是最快的，但也是最危险的——两个进程同时往同一个地址写东西，
没有同步保护的话，会发生什么？
（答案：跟两个人同时改同一个 Google Doc 一样，数据错乱）
```

---

## 一句话总结

> **进程间通信的本质，是在"隔离"的前提下找到"交流"的通道。**
>
> - **管道**：像水管，流式、单向、简单
> - **消息队列**：像邮筒，有边界、异步、内容独立
> - **共享内存**：像共享阳台，最快但需要自己加锁
> - **Unix Socket**：像微信，双向、有边界、功能最强
