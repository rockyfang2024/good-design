# 6.1 进程调度：谁该获得 CPU？

> 操作系统最核心的问题之一：当 CPU 只有 1 个，但进程有 N 个时，怎么分配？

---

## 问题

- 交互进程需要快速响应（几毫秒）
- 后台批处理需要高吞吐（完成更多任务）
- 有些进程是 CPU 密集型，有些是 I/O 密集型
- 不能让任何进程"饿死"

---

## 经典解法

### MLFQ（多级反馈队列）

```
队列 0（最高优先级）: RR, 时间片=8ms   ← 交互进程
队列 1（中优先级）  : RR, 时间片=16ms
队列 2（低优先级）  : RR, 时间片=32ms  ← 批处理
队列 3（更低优先级）: FCFS             ← 沉睡进程
```

**规则：**
1. 新进程先入队列 0
2. 用完时间片还没完成 → 降级到下一队列
3. I/O 阻塞后 → 提升回高优先级（I/O 密集型会被照顾）
4. 每层队列用完才去下一层

**效果**：
- 短任务（交互）快速完成
- 长任务自动沉底，不饿死短任务
- I/O 密集型自动获得高优先级

这是 **BSD Unix** 和早期 Windows 使用的方案。

### CFS（完全公平调度器，Linux）

不给每个进程分配固定时间片，而是维护一棵**红黑树**：

```
                时间线 →
进程A ████░░░░░░░░░  已运行 30ms
进程B ██░░░░░░░░░░░░  已运行 10ms
进程C ████████████░░  已运行 80ms ← 需要被调度

按"已运行时间"排序，最少的最高优先 → CFS 总选择最"饿"的
```

**核心思想**：不是"时间片轮转"，而是"让每个进程都公平地获得 CPU"。

CFS 的关键参数：
- `sched_latency`：一个调度周期多长（默认 6ms）
- `minGranularity`：最小时间粒度（防止切换太频繁）
- `nice` 值：权重，越大优先级越低

### 对比

| 维度 | MLFQ | CFS |
|------|------|-----|
| 核心思想 | 多层队列降级 | 完美公平的红黑树 |
| 响应速度 | 快（高优先级先跑） | 取决于树的深度（通常也很快） |
| 吞吐 | 中等（可能有调度开销） | 高（树操作 O(log n)） |
| 复杂度 | 中等 | 高 |
| 代表系统 | BSD, Windows NT | Linux |

## 扩展：实时调度（RT Scheduling）

**问题**：工业控制、医疗设备、机器人——这些场景要求调度延迟可预测，且有上限。

**实时系统分类**：

```
硬实时（Hard Real-Time）：错过截止时间 = 灾难性故障
  → 航空控制系统、医疗输液泵
  → 调度策略：Rate Monotonic (RM) / Earliest Deadline First (EDF)

软实时（Soft Real-Time）：偶尔错过截止时间可接受
  → 视频播放（丢帧可以，但卡顿不行）
  → 调度策略：POSIX 实时调度（SCHED_FIFO / SCHED_RR / SCHED_DEADLINE）
```

**Linux 实时调度配置**：

```bash
# 查看当前调度策略
chrt -p $$

# 将进程设为 FIFO 实时调度，优先级 50
chrt -f 50 -p 12345

# DEADLINE 调度（最硬核的实时）：任务有三元组 (runtime, period, deadline)
chrt -d --sched-runtime 100000 --sched-deadline 200000 --sched-period 300000 -p 12345
```

**实时性的代价**：优先级高的任务会抢占其他任务，可能导致"饿死"。普通进程的延迟无法保证。

## 扩展：组调度与 CPU Bandwidth Controller

**问题**：一个捣乱进程可能吃掉整台机器的 CPU。怎么限制"每个用户/组/容器"最多只能用 X% 的 CPU？

**解决方案**：Linux CFS Group Scheduler + CPU Bandwidth Controller

```bash
# 创建一个 CPU bandwidth controller（cgroup v2）
# 限制整个 group 最多使用 50% 的 CPU 时间

# /sys/fs/cgroup/system.slice/background.service/cpu.max
# 格式：max 或 "quota period"
echo "50000 100000" > /sys/fs/cgroup/system.slice/background.service/cpu.max
# 50000/100000 = 50% CPU 带宽
```

**CFS 带宽控制器算法**：

```python
# 每个周期（period），每个组最多只能使用 quota 的时间
def check_bandwidth(cgroup):
    used = cgroup.cpu_usage_this_period
    quota = cgroup.cpu_quota

    if used > quota:
        # 这个 cgroup 超过配额，暂停调度直到下个周期
        throttle(cgroup)
    else:
        schedule(cgroup)
```
