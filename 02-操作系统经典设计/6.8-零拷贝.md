# 6.8 零拷贝：从磁盘到网络的捷径

> 传统的数据传递路径有 4 次拷贝、2 次上下文切换。服务器传输大文件时开销极大。

---

## 问题

```
磁盘 ──read()──→ 用户缓冲区 ──write()──→ Socket 缓冲区 ──→ 网络
        ↑                              ↑
      2次拷贝                      2次上下文切换
```

4 次数据拷贝，2 次上下文切换。服务器传输大文件时开销极大。

---

## 经典解法：sendfile()

```
磁盘 ────→ 用户缓冲区（完全绕过）───→ Socket ──→ 网络
          DMA 零拷贝                 2次系统调用，无用户态copy

Linux 实现：
sendfile(socket_fd, file_fd, NULL, file_size);
      │
      ├─ DMA 把文件内容复制到 Socket 缓冲区（内核内部）
      ├─ 协议栈封装 TCP/IP 头
      └─ 网卡发送
```

**零拷贝的关键**：CPU 不参与数据搬运，数据直接在 内核缓冲区 之间传递。

---

## 进阶：RDMA（远程直接内存访问）

```
传统：CPU 参与数据拷贝
RDMA：网卡直接读写另一台机器的内存，CPU 零参与
      网络 ──DMA──→ 对方内存（零拷贝、零 CPU 开销）

用于：高性能计算集群、分布式数据库（InfiniBand）
```

---

## 扩展：DPDK 与高性能网络

**问题**：传统 Linux 网络栈经过多次上下文切换（网卡→内核→用户），在 100Gbps 级别遇到瓶颈。怎么绕过内核？

### DPDK（Data Plane Development Kit）

```
传统路径（每包）：
  网卡 → 内核驱动 → Linux 内核网络栈 → 用户态
  （每步都有中断、上下文切换、内存拷贝）

DPDK 路径（轮询模式）：
  网卡 → DPDK 驱动 → 用户态（完全绕过内核）
  （无中断、无上下文切换，polling 模式）

DPDK 工作原理：
  1. 锁定网卡（igb_uio/vfio 驱动）
  2. 用户进程直接读写网卡的 DMA 环形缓冲区
  3. 用大页（HugePages）避免 TLB miss
  4. 零拷贝：网包数据直接送到用户态的 mbuf
```

### 性能对比

```
场景：10Gbps 网络，64 字节小包

传统方案：最多 ~1Mpps（每秒百万包）
io_uring：~2-3Mpps（减少系统调用开销）
DPDK：~10-15Mpps（完全绕过内核）

代价：
  - DPDK 需要专用 CPU 核（不能运行其他任务）
  - 需要大页内存（2MB/1GB）
  - 无法与其他进程共享网卡
  - 开发复杂度高

典型应用：高性能负载均衡器（DPDK + VPP）、金融交易系统、5G UPF
```

### 演进路径

```
传统：                       零拷贝：
用户 → 内核 → 网卡            用户 → 内核 → 网卡
  ↓       ↓                     ↓      ↑
磁盘 → 用户 → 内核             磁盘 → 内核（DMA）→ 网卡

DPDK（完全绕过内核）：
磁盘 → 用户态 mbuf → 网卡（ring buffer）
```
