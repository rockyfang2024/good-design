# 6.8 零拷贝：从磁盘到网络的捷径

> 传统的数据传递路径有 4 次拷贝、2 次上下文切换。服务器传输大文件时开销极大。
>
> **类比**：餐厅里，顾客点了份宫保鸡丁。传统流程是：厨师做好 → 端到前台 → 服务员端到顾客桌。但如果让顾客直接进厨房自己端（减少传递环节），速度会快很多。

---

## 生活场景：工厂流水线 vs 顾客自己拿

```
传统方式（多次搬运）：
  原材料 → 工厂流水线 → 仓库A → 仓库B → 包装车间 → 顾客
  问题：每个环节都要搬运、等待、清点

零拷贝方式（减少搬运）：
  原材料 → 工厂流水线（直接到顾客手里）
  仓库A、仓库B 都不需要了，减去中间步骤
```

---

## 问题

```
传统 read() → write() 路径：
  磁盘 ──read()──→ 用户缓冲区 ──write()──→ Socket 缓冲区 ──→ 网络
        ↑                              ↑
      2次拷贝                      2次上下文切换
        ↑
  内核态 ↔ 用户态切换 2 次
  总计：4 次拷贝，2 次上下文切换
```

**为什么糟糕**：
- 每秒传 10 万个小文件？10 万次上下文切换 → CPU 大量时间在做"搬家"而非"计算"
- 网卡和磁盘都是高速设备，却被 CPU 这个"搬运工"拖了后腿

---

## 解法一：sendfile() ——"内部传递"

**类比**：厨师做好菜，直接从厨房窗口递出去，不经过前台。顾客从窗口拿。

```
传统方式（4 次拷贝）：
  磁盘 → 用户缓冲区 → Socket → 网卡
        ↑              ↑
     内核→用户       用户→内核

sendfile（2 次拷贝）：
  磁盘 → Socket 缓冲区（内核内部）→ 网卡
        完全在厨房（内核）内部完成
```

```c
// 一行代码实现零拷贝
sendfile(socket_fd, file_fd, NULL, file_size);
// 参数：socket文件描述符, 文件描述符, 偏移, 长度
//        ↓
// 内核内部：
// 1. DMA 把文件内容从磁盘复制到 Socket 缓冲区
// 2. 协议栈封装 TCP/IP 头
// 3. 网卡发送
```

**关键**：CPU 不参与数据搬运，数据直接在内核缓冲区之间传递。

---

## 解法二：mmap ——"阳台共享"

**类比**：把仓库的门打开，让货车直接进仓库拉货，不需要在门口再搬一次。

```c
// 把文件映射到内存
int fd = open("bigfile.dat", O_RDONLY);
void *ptr = mmap(NULL, file_size, PROT_READ, MAP_PRIVATE, fd, 0);

// 读取文件内容（直接读内存，实际上是读磁盘）
// 没有用户态和内核态之间的数据拷贝
process_data(ptr, file_size);
```

**mmap 的工作原理**：
```
传统 read()：
  磁盘 → 内核缓冲区 → 用户缓冲区 → 你用的变量
  2 次拷贝

mmap：
  磁盘 → 内核缓冲区 → 你用的变量（映射）
  1 次拷贝（访问时触发缺页异常，内核加载）
```

---

## 解法三：RDMA ——"直接进别人家仓库搬货"

**类比**：传统方式是"我运货到你家"，RDMA 是"你直接进我的仓库拿，我不用动"。

```
传统网络传输：
  机器A：读取本地内存 → 发送到网卡 → 网络 → 机器B网卡 → 写入内存
  数据经过：内存→网卡→内存（机器A）和 网卡→内存（机器B）

RDMA：
  机器A：授权机器B"可以远程读取我这块内存"
  机器B：直接通过网卡读取机器A的指定内存区域
  零拷贝、零 CPU 参与
```

**应用场景**：
- 高性能计算集群（GPU 之间传数据）
- 分布式数据库（InfiniBand 网络）
- 金融交易系统（延迟敏感）

---

## 进阶：DPDK ——"绕过物业，直接进小区"

**问题**：传统 Linux 网络栈经过多次上下文切换（网卡→内核→用户），在 100Gbps 级别遇到瓶颈。

**类比**：传统方式是"快递→物业→收件人"，DPDK 是"快递员直接敲门送货"。

### DPDK（Data Plane Development Kit）

```
传统路径（每包都有关卡）：
  网卡 → 内核驱动（中断） → Linux 内核网络栈 → 用户态
  每步都有：中断、上下文切换、内存拷贝

DPDK 路径（畅通无阻）：
  网卡 → DPDK 驱动 → 用户态（完全绕过内核）
  轮询模式（polling），无中断、无切换

DPDK 工作原理：
  1. 锁定网卡（igb_uio/vfio 驱动）—— 其他进程不能用
  2. 用户进程直接读写网卡的 DMA 环形缓冲区
  3. 用大页（HugePages）—— 减少 TLB miss
  4. 零拷贝——网包数据直接送到用户态的 mbuf
```

### 性能对比

```
场景：10Gbps 网络，64 字节小包

传统方案：最多 ~1Mpps（每秒百万包）
  → 中断和上下文切换成为瓶颈

io_uring：~2-3Mpps
  → 减少系统调用开销

DPDK：~10-15Mpps
  → 完全绕过内核，极致性能

代价（高收益有高成本）：
  ✗ 需要专用 CPU 核（不能跑其他任务）
  ✗ 需要大页内存（2MB/1GB）
  ✗ 无法与其他进程共享网卡
  ✗ 开发复杂度高，debug 困难
```

**典型应用**：
- DPDK + VPP（Vector Packet Processing）：高性能负载均衡器
- 金融交易系统：每微秒都可能损失金钱
- 5G UPF（User Plane Function）：5G 核心网用户面

---

## 演进路径图

```
传统（每次都过物业）：
用户 → 内核 → 网卡
  ↓       ↓
磁盘 → 用户 → 内核

零拷贝（内部传递，不过用户层）：
磁盘 → 内核（DMA）→ 网卡

DPDK（绕过物业，直接敲门）：
磁盘 → 用户态 mbuf → 网卡（ring buffer）
```

---

## 一句话总结

> **零拷贝的本质，是减少数据在"内核态"和"用户态"之间的来回搬运——最好的拷贝是根本不拷贝。**
>
> - **sendfile()**：内核内部直接转发，不经过用户态
> - **mmap()**：文件映射到内存，减少一次拷贝
> - **RDMA**：网卡直接读写对方内存，CPU 零参与
> - **DPDK**：完全绕过内核，用专用 CPU 核处理网络
