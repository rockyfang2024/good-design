# 6.4 文件系统：如何持久化存储

> 磁盘上要存几十亿个文件，每个文件有名字、大小、时间戳、内容。怎么组织？

---

## 问题

- 文件名变长、变短 → 不能预分配固定大小
- 删除文件 → 产生空洞，不能浪费空间
- 目录层级深 → 需要高效查找
- 突然断电 → 不能丢数据

---

## 经典解法

### inode + 块组（Unix 文件系统的基石）

```
磁盘布局：
┌─────────┬────────────┬─────────────┬────────────┐
│ Super   │ Block      │  inode 表   │  数据块    │
│ Block   │ Group      │  (索引节点) │            │
│(文件系统│ Descriptors│             │            │
│ 元数据) │            │  inode 0   │  block 0   │
└─────────┴────────────┴─────────────┴────────────┘

inode 结构（ext2/ext3/ext4）：
┌──────────┬──────────────────────────────┐
│ metadata │  data blocks (直接/间接/双间接)│
├──────────┼──────────────────────────────┤
│ mode     │  block[12]   ← 12个直接块     │
│ uid      │  block[12]   ← 1K * 12 = 12KB │
│ size     │  block[13]   ← 单间接块指针   │
│ atime    │  block[14]   ← 双间接块指针   │
│ mtime    │  block[15]   ← 三间接块指针   │
│ blocks   │  ...                        │
│ links    │                              │
└──────────┴──────────────────────────────┘
            每个块 1KB → 最大文件 4GB+（用间接块扩展）
```

### 为什么用 inode 而非连续分配？

```
连续分配：文件 A 占 block 0-9，文件 B 占 block 10-19
→ 问题：删了 A，空出 block 0-9，B 不能自动长大填进去 → 碎片化

inode：文件是 block 指针的集合
→ 文件可以散布在磁盘任何位置，按需分配
→ 删除文件只是释放指针指向的块，不影响其他文件
```

### 日志文件系统（Journaling）

**问题**：写文件时突然断电，可能只写了一半，文件系统进入不一致状态。

**解法**：Write-Ahead Log（日志）

```
正常文件系统写入：
    直接写磁盘（可能有中间不一致状态）

日志文件系统写入：
    1. 把要写的东西先记到"日志区"（顺序写入，很快）
       - TxB: 开始事务
       - [要修改的块内容]
       - TxE: 结束事务

    2. 确认日志落盘后，再去修改实际位置（后台）

    3. 完成后标记日志为"完成"

崩溃恢复：
    检查日志 → 有未完成事务 → 重做（REDO）或撤销（UNDO）
    → 文件系统恢复到一致状态
```

**代表系统**：ext3/ext4, NTFS, JFS, XFS 都使用日志（只是 ext3/ext4 是"日志数据"模式，而 ext4 是"日志摘要"模式更复杂）。

### 命名管道（FIFO）与 UNIX Domain Socket

同一台机器上进程间通信：

```
进程 A（生产者）                          进程 B（消费者）
      │                                       ▲
      │ write("hello")                        │
      ├─────────────────── pipe ──────────────┤
      │                                       │
```

```c
// 创建管道
int pipefd[2];
pipe(pipefd);  // pipefd[0]=读端, pipefd[1]=写端

// 写
write(pipefd[1], "hello", 5);

// 读
read(pipefd[0], buf, 5);
```

**管道是字节流**（没有消息边界），**Socket 是消息边界**。

## 扩展：VFS（虚拟文件系统层）

**问题**：Linux 需要同时支持 ext4、XFS、Btrfs、NFS、CIFS……几十种文件系统。每种接口都不一样。怎么让应用程序用统一的接口访问所有文件系统？

**解决方案：VFS 抽象层**

```
                应用程序
                   │
        open() read() write() mkdir()  ← 统一的 POSIX API
                   │
          ┌────────┴────────┐
          ▼                 ▼
    ┌──────────┐    ┌──────────┐    ┌──────────┐
    │   ext4   │    │   XFS    │    │   NFS    │
    │ 文件系统  │    │ 文件系统  │    │ 文件系统  │
    └──────────┘    └──────────┘    └──────────┘
          ▲                 ▲            ▲
          └────────┬────────┴────────────┘
                   ▼
            VFS（虚拟文件系统层）
              │
    ┌─────────┼─────────┐
    ▼         ▼         ▼
  super_block  inode   dentry
    (整个文件系统)  (单个文件)  (目录项缓存)
```

**VFS 的四个核心对象**：

```c
struct super_block    // 整个文件系统的元数据
struct inode         // 单个文件的元数据（inode）
struct dentry        // 目录项缓存（路径名 → inode 的映射）
struct file          // 进程打开的文件实例（包含读写位置等）

// 每个文件系统必须实现一组操作函数指针
struct file_operations {
    ssize_t (*read)(struct file *, char __user *, size_t, loff_t *);
    ssize_t (*write)(struct file *, const char __user *, size_t, loff_t *);
    int     (*open)(struct inode *, struct file *);
    int     (*release)(struct inode *, struct file *);
    loff_t  (*llseek)(struct file *, loff_t, int);
    // ...
};
```

**dentry 缓存（目录项缓存）**：

```
路径解析：
  /home/ubuntu/file.txt
  ↑
  首先查 dentry 缓存（最近访问的路径）
  ↓ 未命中
  逐级查 inode：root inode → home inode → ubuntu inode → file inode
  ↓
  dentry 缓存会缓存每一级，下次访问时直接命中
```
